## Required behavior

### 1. The ids (spec §5.4)

A handle belongs to one split, named by the id of the first leaf of
its later child. That id names exactly one split. Add to the
`define-methods` block:

```aloe
    ;; The id of the first leaf, in layout order.
    (first-id () Int
      (self case
        (Leaf (view) (view id))
        (Below (top bottom earlier later) (top first-id))
        (Right (left right earlier later) (left first-id))))

    ;; The id that names this split: the first leaf of its later child. On
    ;; a leaf, the leaf's own id; a leaf is never a handle.
    (handle-id () Int
      (self case
        (Leaf (view) (view id))
        (Below (top bottom earlier later) (bottom first-id))
        (Right (left right earlier later) (right first-id))))
```

Pinned: on `srrr`'s tree (below), `first-id` is 0 and `handle-id` is
1; its left child's `handle-id` is 2; the innermost `Right`'s is 3.
On `sbr`'s tree, `handle-id` is 1 and the top child's is 2.

### 2. The structural floor, column axis (spec §5.3)

A drag never leaves a leaf narrower than one column, counting every
leaf of both children of the dragged split, each child divided by
the weights it already has. This can be pasted as it is:

```aloe
    ;; The smallest columns at or above the start whose cut, by this Right's
    ;; own weights, gives the left at least left-least and the right at
    ;; least right-least.
    (columns-from (columns Int) (left-least Int) (right-least Int) (earlier Int) (later Int) Int
      (let ((probe (AloemacsWindowRect new 0 0 columns 0)))
        (let ((cut (probe column-cut earlier later))
              (extent (columns - (probe divider columns))))
          (if (if (cut >= left-least) ((extent - cut) >= right-least) #f)
              columns
              (self columns-from (columns + 1) left-least right-least earlier later)))))

    ;; The narrowest width at which every leaf keeps one column, each child
    ;; divided by its own weights.
    (min-columns () Int
      (self case
        (Leaf (view) 1)
        (Below (top bottom earlier later) ((top min-columns) max (bottom min-columns)))
        (Right (left right earlier later)
          (self columns-from (((left min-columns) + (right min-columns)) + 1)
            (left min-columns) (right min-columns) earlier later))))
```

The search starts at the sum of the children's minimums plus the
divider and climbs by one; it terminates because the cut and its
remainder both grow without bound. The sum is where the search
starts, not the answer: a `Right (Right (A, B), C)` needs 6 columns
at equal weights, not 5, because the equal cut of 5 is 2 and 2 and
the inner cut of 2 is 1 and 0. Pinned values, every weight `1 1`
unless written:

| Tree | `min-columns` |
|---|---:|
| `Leaf` | 1 |
| `Below (A, B)` | 1 |
| `Right (A, B)` | 3 |
| `Right (A, B)` with `1 78` or `78 1` | 3 |
| `Below (Right (A, B), C)` | 3 |
| `Right (Below (A, B), C)` | 3 |
| `Below (Below (A, B), C)` | 1 |
| `Below (Below (A, B), C)` with the outer `4 8` | 1 |
| `Right (Right (A, B), C)` | 6 |
| `Below (Below (Below (A, B), C), D)` | 1 |
| `Right (Right (Right (A, B), C), D)` | 12 |

`min-rows` and `rows-from` do not exist in this checkpoint.

### 3. The walk (spec §5.4)

One walk from the root with the rectangles `rect-for` walks. The
ancestor wins. In this checkpoint a `Below` has no boundary check
and only recurses. This can be pasted as it is:

```aloe
    ;; The split whose handle holds the cell: a Right's bar column. A Below
    ;; only descends here; its boundary row is 003's. None for a leaf or a
    ;; cell outside.
    (handle-at (column Int) (row Int) (rect AloemacsWindowRect) (Option AloemacsWindowTree)
      (self case
        (Leaf (view) (Option None))
        (Below (top bottom earlier later)
          (if (rect contains? column row)
              ((top handle-at column row (rect top earlier later)) case
                (Some (found) (Option Some found))
                (None () (bottom handle-at column row (rect bottom earlier later))))
              (Option None)))
        (Right (left right earlier later)
          (if (rect contains? column row)
              (if (column = ((rect x) + (rect column-cut earlier later)))
                  (Option Some self)
                  ((left handle-at column row (rect left earlier later)) case
                    (Some (found) (Option Some found))
                    (None () (right handle-at column row (rect right earlier later)))))
              (Option None)))))
```

Pinned, with root `(AloemacsWindowRect new 0 0 80 23)`: on `sr`'s
tree, `handle-at 40 5` is `Some` of the root, and `handle-at 39 5`,
`handle-at 41 5`, and `handle-at 40 23` are `None`. On `srr`'s tree,
`handle-at 20 0` is the inner `Right` and `handle-at 40 0` is the
root. On `sbr`'s tree, `handle-at 40 3` is the inner `Right`, and
`handle-at 0 11` is `None`. `handle-at 40 11` on `sbr`'s tree, the
bar cell on the boundary row, answers the inner `Right` in this
checkpoint and the `Below` after 003; do not pin it either way.

### 4. What a move writes, column axis (spec §5.6)

A move while armed maps the pointer to a cut for the armed split, in
the rectangle that split has under the last fit, clamped to the
structural interval, and writes the two cell counts as the weights.
In this checkpoint the `Below` arm has only its two descents and
`else`. This can be pasted as it is:

```aloe
    ;; Rewrite the weights of the split that id names, from a pointer cell,
    ;; in the rectangle the split has under rect. The tree is unchanged when
    ;; no split has that id or the interval is empty. A Below only descends
    ;; here; its own rewrite is 003's.
    (with-cut-at (id Int) (column Int) (row Int) (rect AloemacsWindowRect) AloemacsWindowTree
      (self case
        (Leaf (view) self)
        (Below (top bottom earlier later)
          (cond
            (((top find-view id) present?)
              (AloemacsWindowTree Below
                (top with-cut-at id column row (rect top earlier later)) bottom earlier later))
            (((bottom find-view id) present?)
              (AloemacsWindowTree Below
                top (bottom with-cut-at id column row (rect bottom earlier later)) earlier later))
            (else self)))
        (Right (left right earlier later)
          (cond
            (((right first-id) = id)
              (let ((extent ((rect columns) - (rect divider (rect columns))))
                    (lo (left min-columns)))
                (let ((hi (extent - (right min-columns))))
                  (if (lo > hi)
                      self
                      (let ((cut (lo max ((column - (rect x)) min hi))))
                        (AloemacsWindowTree Right left right cut (extent - cut)))))))
            (((left find-view id) present?)
              (AloemacsWindowTree Right
                (left with-cut-at id column row (rect left earlier later)) right earlier later))
            (((right find-view id) present?)
              (AloemacsWindowTree Right
                left (right with-cut-at id column row (rect right earlier later)) earlier later))
            (else self)))))
```

In words, for a `Right`: `wanted = column - rect.x`;
`extent = columns - divider`; `cut` is `wanted` clamped to
`[min-columns (left), extent - min-columns (right)]`; the weights
become `cut, extent - cut`. An empty interval leaves the tree. A
pointer outside the split's rectangle, or outside the root, is
clamped, not refused. The children are unchanged by a rewrite; only
the two weights are new. At the size of the drag, §5.2's `cut`
reproduces the written cut exactly, so the next frame paints the bar
at the pointer column.

### 5. The session: `press-handle` and `drag-to` (spec §5.5)

Add before `press-at`. This can be pasted as it is:

```aloe
    ;; Arm the split whose handle holds the cell, unless a leaf in either
    ;; child is locked or the tree does not fit.
    (press-handle (column Int) (row Int) (AloemacsSession H)
      (let ((windows (self windows)))
        (let ((root (self root-rect (windows columns) (windows rows))))
          (if ((windows tree) positive-layout? root)
              (((windows tree) handle-at column row root) case
                (None () (self unchanged))
                (Some (split)
                  (if (split any-locked?)
                      (self unchanged)
                      (self with (windows (windows armed (split handle-id)))))))
              (self unchanged)))))

    ;; Rewrite the armed split's weights from the pointer. Nothing armed, or
    ;; a tree that does not fit, leaves the session.
    (drag-to (column Int) (row Int) (AloemacsSession H)
      (let ((windows (self windows)))
        ((windows drag) case
          (None () (self unchanged))
          (Some (id)
            (let ((root (self root-rect (windows columns) (windows rows))))
              (if ((windows tree) positive-layout? root)
                  (self with
                    (windows
                      (windows with (tree ((windows tree) with-cut-at id column row root)))))
                  (self unchanged)))))))
```

Then two one-line replacements:

- In `press-at`, the `None` arm directly under
  `(((windows tree) view-at column row root) case` becomes
  `(None () (self press-handle column row))`. The `None` arm under
  `rect-for`, two lines below, stays `(self unchanged)`.
- In `handle-mouse`, `((mouse move?) (self unchanged))` becomes
  `((mouse move?) (self drag-to (mouse column) (mouse row)))`.

`press-handle` runs only from the no-leaf arm: a bar cell, or a cell
outside every leaf. `press-mode-line`'s `""` branch still returns
`(self unchanged)`; 003 routes it here. `handle-event` is unchanged:
a key still disarms before `handle-key`. `handle-mouse` keeps its
three refusals, and a left press still disarms before `press-at`, so
a press on a handle re-arms that handle and a press elsewhere takes
today's path with `drag` `None`. `root-rect` is the completion-aware
root, so a handle is classified with the geometry of the last fit,
never with `(term columns)` or `(term rows)`. `(split any-locked?)`
is true when any leaf of either child is locked (§5.7): the refusal
is blanket over the split's two children, not over the tree.

A move rewrites weights with no fit and no echo. The runner's next
`ensure-visible` and frame read the weights back; that fit may
scroll the selected window to keep its point inside its new
rectangle, as after a terminal resize. The drag stores no origin,
changes no point, and changes no selection. A terminal resize between
events keeps the armed id; the next move uses the new geometry. The
press alone and the release alone paint the frame painted before
them.

### 6. The event table as this checkpoint implements it (spec §5.5)

| Event | While not armed | While armed |
|---|---|---|
| `mouse down left` on a bar of a split with no locked leaf in either child | Arms. Nothing else changes: selection, points, origins, echo, frame | Re-arms on that handle. Nothing else changes |
| `mouse down left` on a bar of a split with a locked leaf in either child | Unchanged | Disarms. Nothing else changes |
| `mouse down left` anywhere else, including a mode-line cell | Today's path: a label is its command, text places, chrome is unchanged | Disarms, then today's path |
| `mouse move` | Unchanged | Rewrites the armed `Right`'s weights per §4. A missing split, an empty interval, or a non-positive layout leaves the tree |
| `mouse up left` | Unchanged | Disarms. The weights stay what the last move wrote |
| `mouse down` or `mouse up` with middle or right | Unchanged | Disarms. Nothing else changes |
| A key | Today's path | Disarms, then today's path |
| Any mouse string during a search, a prompt, or a pending prefix | Unchanged | Unchanged |
| Any event after quit | Unchanged | Unchanged |
